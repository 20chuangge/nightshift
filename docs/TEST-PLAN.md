# Nightshift 空白机测试方案

目标：在一台**从没装过 Nightshift 的机器**上，从下载安装包到"助理在远程机器上干完一件事"，每一步都有明确的通过标准。发布前跑一遍；新增系统支持时也跑一遍。

## 0. 测试矩阵

| 角色 | 系统 | 来源 | 必测 |
| --- | --- | --- | --- |
| 本机（装客户端） | Windows 11 x64，新用户账号 | 虚拟机快照 / 新建用户 | ✅ |
| 本机 | Windows 10 22H2 | 虚拟机 | 发版前 |
| 远程机 | Ubuntu 24.04 / 22.04 Server（最小安装） | 虚拟机或云主机 | ✅ |
| 远程机 | Rocky Linux 9（最小安装） | 虚拟机或云主机 | ✅ |
| 远程机 | Windows 11 / Windows Server 2022 | 虚拟机 | ✅ |
| 远程机 | 1 核 2 GB 的小机器 | 云主机最低配 | 发版前 |

**每台机器都从快照恢复到"刚装好系统"**：没有 Node、没有 git、没有桌面组件。远程机只要求：能 SSH 登录、账号有 sudo（Linux）或是管理员（Windows）。Windows 远程机要先开 OpenSSH Server：

```powershell
Add-WindowsCapability -Online -Name OpenSSH.Server~~~~0.0.1.0
Set-Service sshd -StartupType Automatic; Start-Service sshd
```

## 2. 本机：装客户端

| # | 操作 | 通过标准 |
| --- | --- | --- |
| 2.1 | 双击 `Nightshift-Setup-x.y.z.exe` | 不需要管理员；安装完成后自动打开 |
| 2.2 | 首次打开 | 5 秒内出现主界面；左上是"本机"；有一个默认 Bot"助理"；空聊天显示助理头像和 4 个示例 |
| 2.3 | 端口被占用（先 `npx http-server -p 14390`） | 仍能打开（自动换端口），重开后记住新端口 |
| 2.4 | 设置 → 模型：填 Key，点"测试" | 显示连通；随便发一句话能收到回复 |
| 2.5 | 发"看看这台电脑" | 助理调工具，回答 CPU / 内存 / 磁盘 |
| 2.6 | 发"在桌面建个文件 hello.txt" | **本机要审批**：弹出审批卡，批准后才执行 |
| 2.7 | 附件：拖入一张图片和一个 txt，粘贴一张截图 | 输入框上出现 3 个附件卡；发送后气泡里显示缩略图和文件卡；助理能说出 txt 里的内容 |
| 2.8 | 切换英文 / 深色主题 | 没有残留中文；重开后保持 |
| 2.9 | 关掉窗口再开 | 聊天记录、Bot、群都还在 |
| 2.10 | 覆盖安装新版本 | 数据保留（`%APPDATA%\Desk`） |
| 2.11 | 设置 → 权限 | 顶部先是「权限总览」：芯片显示审批级别/接管/生成/其他位置/sudo/规则数；表格按 Bot 列出 8 项能力，并按当前级别显示 ✓ 直接做 / 问 先问你 / — 未授权（切换级别实时变化）；新增或删除 Bot 后表格行同步增减；点「一键 strict」二次确认后五项边界收紧，审计出现一条 `policy.changed`，Bot 工具授权不变 |
| 2.12 | 设置 → 成本 | 发几句话后：今日/14 天 tokens 与估算、按 Bot 表格、按天条形出现；给模型填单价并保存后估算变为金额，未定价 tokens 归零；把每日提醒设成很小值再发一句话，弹出提醒并写一条 `usage.alert` 审计（当天只记一次）；测试后把单价与提醒还原 |

## 3. 添加远程机（每个远程系统各跑一遍）

在客户端：机器 → 添加机器 → 填 IP、账号、密码 → 开始。

| # | 检查 | 通过标准 |
| --- | --- | --- |
| 3.1 | 进度 | 显示 1/7 … 7/7，每步有中文说明；Linux 全程 < 10 分钟，Windows < 15 分钟 |
| 3.2 | 结果 | 出现"已添加"，机器列表里多一台，自动切换过去 |
| 3.3 | 模型 | **不用再填 Key**：新机器直接能对话（模型随添加同步过去） |
| 3.4 | Bot | 新机器有自己的"助理"，和本机的 Bot 列表互不影响 |
| 3.5 | 审批 | 远程机**不弹审批**：让它建文件、装软件，直接执行 |
| 3.6 | 危险命令 | 让它 `rm -rf /` / `format C:` / 关闭 SSH | 被拒绝，并说明原因 |
| 3.7 | 屏幕 | 打开"屏幕"：10 秒内看到桌面（Linux 是 Bot 自己的 XFCE；Windows 是控制台桌面） |
| 3.8 | 接管 | 点"接管"能用鼠标键盘操作；"交还"后 Bot 继续 |
| 3.9 | 浏览器 | 发"打开 example.com 截个图" | 屏幕里能看到浏览器打开，聊天里有截图 |
| 3.10 | 重启远程机 | 2 分钟内机器重新在线，屏幕、对话照常 |
| 3.11 | 再添加一次同一台 | 原地升级，不丢 Bot 和聊天 |

验收脚本可以替代 3.1–3.5 的大部分人工检查：

```bash
DESK_TARGET_HOST=<ip> DESK_TARGET_USER=<user> DESK_TARGET_PASS=<pass> npm run verify:remote
```

结论必须是 `PASS`。

**安全检查**（每个远程系统）：

- 在另一台机器上 `nmap -p 5900,6080-6200 <ip>`：VNC / websockify 端口**不可从外部访问**（只听 127.0.0.1）
- 不配对直接访问 `http://<ip>:4390/api/bots`：返回 401
- 不配对直接连 `/api/bots/<id>/desktop/ws`：被拒绝

## 4. 多机器与协作

| # | 操作 | 通过标准 |
| --- | --- | --- |
| 4.1 | 本机 + 2 台远程机，来回切换 | 整个界面（Bot、群、聊天、屏幕）跟着切换，没有串台 |
| 4.2 | 对助理说"列出所有机器" / "切到 xxx" | `machine_list` / `machine_switch` 生效 |
| 4.3 | 对助理说"建一个叫研究员的 Bot，再建个群把我们俩拉进去" | Bot 和群都建好，群里能对话 |
| 4.4 | 设置 → 模型 → 同步到所有机器 | 每台都显示同步成功；改模型后各机器都用新模型 |
| 4.5 | 定时任务："每天 9 点汇报磁盘使用" | 到点执行，结果出现在聊天里 |
| 4.6 | 手机配对一台电脑；让助理做一件要审批的事，锁屏 | 手机通知出现，展开是一张卡片：Bot 名、「在等你」、动作与详情、原因、两个按钮 |
| 4.7 | 在通知卡上点「允许这一次」 | 电脑上的审批卡变为已处理并继续跑；`data/audit.jsonl` 里 `by` 为 `device`，备注「手机通知」 |
| 4.8 | 两台电脑都在线时，从非默认那台发起审批，再点通知 | 打开的是那台电脑的界面，并定位、高亮对应审批卡 |
| 4.9 | 断网点「拒绝」 | 通知变成「这一步还没答复」，点开进入审批卡；联网后可在卡上拒绝 |
| 4.10 | 审批还挂在手机上时，在电脑端批准 / 拒绝 | 手机上的对应审批通知自动消失，不留下已答复的卡 |
| 4.11 | 审批等待期间切换 Wi-Fi / 断开网络再恢复 | App 在 45 秒内发现断流并重连；新审批仍能到达通知栏 |
| 4.12 | 手机聊天里点 📎 选一张图发送 | 系统选择器弹出；输入框上方出现缩略图芯片；气泡带图；助理用 image_view 说出图片内容 |
| 4.13 | 手机聊天里点 🎤 说一句话再点停止 | 首次弹系统麦克风授权；允许后录音，停止后转写文字落入输入框（http 局域网下走原生录音桥） |
| 4.14 | 手机上点接管卡的「接管屏幕」 | 面板立即滑出并进入全屏接管，画面下方常驻工具条（键盘/Ctrl/Alt/Esc/Tab/剪贴板/旋转/预览） |
| 4.15 | 接管中点工具条「键盘」再输入 | 系统输入法弹出，按键进入远端（终端回显）；点「旋转」画面转 90°、工具条保持 upright，再点切回 |
| 4.16 | 接管中点「剪贴板」粘贴文本并发送 | 抽屉打开；发送后远端剪贴板收到原文（VNC 标准通道为 latin1，中文提示改用键盘）；「复制到手机」可用 |
| 4.17 | 接管中关闭面板 | iframe 与 VNC 连接立即卸载，不再后台耗流量；重开预览点画面即进全屏 |
| 4.18 | 浅色主题下进入接管全屏 | 右下角「退出全屏」与「我弄好了，继续」清晰可读（固定深底白字/白底黑字，不跟主题）；底部工具条同样清楚 |
| 4.19 | 手机 App 接管中点「旋转」 | 真横屏（系统方向锁定）+ 状态栏/导航栏隐藏；工具条在右侧竖排 44px；再点「竖屏」或退出接管/切后台，恢复竖屏与系统栏；浏览器里不可锁定时退回 CSS 旋转 |
| 4.20 | 三端同连一台 Hub（电脑软件 / 手机 App / 浏览器），逐项改设置 | 模型、审批级别、Bot 名字、生成服务、飞书开关在另外两端 3 秒内自动变化且无需刷新；外观/语言/主题只改本端；切到另一台机器改设置不影响本机 |
| 4.21 | 设置 → 手机和外网 → 外网访问 | 首次开启给出 Tailscale 后台链接；启用后显示 https 地址与「任何网络」二维码；手机断 Wi-Fi/关 Tailscale 后扫码可配对、聊天与审批；关闭后公网地址立即不可用；公网输入 8 位配对码被拒 |

## 5. 异常与恢复

| # | 场景 | 通过标准 |
| --- | --- | --- |
| 5.1 | SSH 密码错 / 用户名错 | 明确提示，**客户端不崩溃** |
| 5.2 | 账号没有 sudo / 不是管理员 | 安装前就说明原因并停止 |
| 5.3 | 远程机不能上外网 | 在下载 Node 那一步失败并说明 |
| 5.4 | 安装中途断网 | 失败提示；网络恢复后重试成功 |
| 5.5 | 远程机关机 | 机器显示离线；开机后自动恢复 |
| 5.6 | 模型 Key 失效 / 欠费 | 聊天里提示，不卡住 |
| 5.7 | 模型偶发 429 / 5xx | 自动重试，用户无感 |
| 5.8 | 上传 30 MB 文件 / 一次 11 个附件 | 明确拒绝（25 MB、10 个上限） |

## 6. 记录与出口标准

每次测试记录：日期、版本号（`git rev-parse --short HEAD`）、每台机器的系统版本、每项 ✅/❌、失败截图和 `%APPDATA%\Desk\logs` / 远程 `journalctl -u desk-hub` / `C:\ProgramData\Nightshift\hub\hub.log`。

**可以发版**：第 1 节全绿；第 2、3 节在 Windows 11 本机 + Ubuntu + Rocky + Windows 远程机上全部 ✅；第 3 节安全检查全部 ✅；第 4、5 节没有 P0 问题（崩溃、数据丢失、安全暴露）。
